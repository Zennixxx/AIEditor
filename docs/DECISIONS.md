# Архитектурные решения

| # | Дата | Решение | Почему | Альтернативы |
|---|---|---|---|---|
| 1 | 2026-10-05 | React + TS (Vite) для UI, Python FastAPI для обработки | интерактивный таймлайн и шейдерное превью проще в браузере; librosa/Demucs/RIFE — экосистема Python | только Python (PyQt) — сложный UI; только браузер — нет RIFE/Demucs; Next.js — SSR не нужен |
| 2 | 2026-10-05 | Экспорт в браузере (WebGL + WebCodecs + Mediabunny) | превью и экспорт используют один рендерер — совпадают кадр в кадр | рендер на Python (moderngl) — дублирование шейдеров; Remotion — лицензия для компаний |
| 3 | 2026-10-05 | RIFE (rife-ncnn-vulkan) вместо Twixtor | Twixtor — закрытый плагин без SDK; RIFE работает на любой GPU через Vulkan | ffmpeg minterpolate (как fallback); экспорт в AE `.jsx` для ручного Twixtor |
| 4 | 2026-10-05 | Маркеры баса — DSP (librosa), не LLM | точность до мс, бесплатно, детерминированно | Gemini по аудио — неточные таймкоды |
| 5 | 2026-10-05 | ИИ меняет проект только через edit-ops с превью и undo | безопасно, проверяемо, тот же механизм для макро-действий UI | прямое редактирование JSON моделью |
| 6 | 2026-10-05 | Автоэдит — детерминированный каркас + Gemini выбирает назначения | стыки всегда точно на маркерах, LLM отвечает только за «вкус» | полностью LLM-план — ошибки в таймкодах |
| 7 | 2026-10-05 | Маркеры музыки хранятся на аудиоклипе в source time | двигаются вместе с клипом, как layer markers в AE | маркеры только композиции |
| 8 | 2026-10-05 | Секции музыки из анализа тоже хранятся на клипе (`clip.sections`, source time); `project.sections` — только секции композиции | секции не разъезжаются с музыкой при сдвиге/триме клипа, нет производного состояния для синхронизации; симметрично маркерам (#7) | секции в `project.sections` с пересчётом при каждом `moveClip`/триме — хрупко; `schemaVersion 2` с удалением `project.sections` — лишняя миграция |
| 9 | 2026-10-06 | Переход — эффект fx-дорожки (adjustment layer) с центром на стыке, шейдер видит один кадр: до середины — клип A, после — B; движение задаётся положением внутри эффекта, сила — огибающей | ложится в существующую модель (`EffectItem` на fx-дорожке, CONTRACT §2 п. 7) без изменения контракта и рендерера; превью = экспорт | переход с двумя входами (A и B одновременно) — нужен перекрывающийся монтаж клипов и новый тип элемента в схеме; кроссфейд прозрачностью — не эдит-стиль |
| 10 | 2026-10-06 | Интерполированный ассет — обычный ассет с `parent` (свой каталог, `/original`, `proxy.mp4`) с PTS исходника (edit list); `clip.interpolatedAssetId` фронт пишет вне истории undo | те же роуты и Range-отдача, превью и экспорт берут кадр по тому же `src(τ)`; ссылка на кэш — производное состояние, undo не должен его откатывать и обрывать redo | каталог `derived/` внутри родителя — отдельные роуты; сдвиг таймкодов на фронте — две системы времени; запись через ops — каждая готовность интерполяции ломала бы redo |
| 11 | 2026-10-06 | Ответ копилота Gemini — union моделей по `op` с плоскими полями и обязательными полями (параметры эффектов — пары строк `{key, value}`), бэк переводит его в строгий `EditOp` и прогоняет на копии проекта | при генерации по схеме поля идут в фиксированном порядке: с одной плоской моделью (все поля необязательные) модель пропускала нужные поля (`start`, `track_id`) — 2 из 10 эталонных команд падали; с union и обязательными полями — 10 из 10 | одна плоская `GeminiOp` (план §7.4); JSON ops строкой внутри ответа |
| 12 | 2026-10-06 | Предпросмотр ops от ИИ — таймлайн рисует проект после сухого прогона `applyOps` (новое — пунктиром, изменённое — контуром), правка заблокирована до «Применить» / «Отклонить»; применение — тот же список ops одной транзакцией | пользователь видит ровно то, что получится (включая раскрытые макро-ops и новые дорожки), без второго механизма отрисовки; undo — одна запись | «призраки» поверх текущего проекта — не показать новые дорожки и раскрытые макро-ops; применить сразу и предложить undo — нарушает принцип «ИИ не меняет проект молча» |
| 13 | 2026-10-06 | Без десктоп-сборки: ни Tauri, ни PyInstaller, ни установщика; приложение запускается `npm run dev` и работает в браузере | пользователю достаточно запуска из репозитория; сборка sidecar и установщика — большой объём работы без пользы для него | Tauri 2 + Python-sidecar (PyInstaller) с установщиком `.exe` (исходный план фазы 8) |
