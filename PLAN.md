# AIEditor — план разработки

ИИ-ассистент для монтажа эдитов под музыку: слои как в After Effects, автоматические маркеры на бассах, библиотека популярных эффектов (шейк, зум-панч, пан-кроп, фликер, RGB-сдвиг…), speed ramp / velocity с интерполяцией кадров, ИИ-копилот на Gemini API.

Этот файл — главный план. Детали:

| Документ | Для кого | Что внутри |
|---|---|---|
| [`CLAUDE.md`](CLAUDE.md) | все агенты | правила работы, зоны ответственности, команды запуска |
| [`docs/CONTRACT.md`](docs/CONTRACT.md) | **оба агента** | схема `project.json`, HTTP/WS API, edit-ops, реестр эффектов, математика speed ramp |
| [`docs/FRONTEND.md`](docs/FRONTEND.md) | агент фронта | задачи по фазам + критерии готовности |
| [`docs/BACKEND.md`](docs/BACKEND.md) | агент Python | задачи по фазам + критерии готовности |

---

## 1. Ключевые решения

1. **Гибрид:** UI на React + TypeScript (Vite), тяжёлая обработка на Python (FastAPI) локально на `127.0.0.1:8765`. Next.js не используется — SSR не нужен.
2. **`project.json` — единый источник правды.** UI его рисует, экспорт его рендерит, ИИ его меняет через **edit-ops** (список операций, применяется одной транзакцией с undo).
3. **Контракт первичен.** Схема и API описаны в `docs/CONTRACT.md` и `shared/`. Фронт и бэк пишутся параллельно против контракта; фронт до готовности бэка работает на моках из `shared/fixtures/`.
4. **Превью = экспорт.** Все эффекты — GLSL-шейдеры в WebGL2. Экспорт рендерится в браузере теми же шейдерами, кодируется WebCodecs, упаковывается в MP4 через Mediabunny. Python в рендере не участвует.
5. **DSP, а не ИИ, для точных вещей.** Маркеры баса, BPM, биты — librosa (+ опц. Demucs). Gemini — для смысла: лучшие моменты в клипах, структура трека, команды на естественном языке, автоэдит, стиль по референсу.
6. **Twixtor не используется** (закрытый плагин без SDK). Замедление — RIFE (`rife-ncnn-vulkan`, Vulkan, любая GPU) на бэке; фронт сэмплирует кадры из интерполированного ассета. Бонус: экспорт проекта в After Effects `.jsx`, чтобы при желании наложить Twixtor там.
7. **Time units:** все времена в JSON — секунды (`float`). Привязка к кадрам делается в UI по `project.fps`.

## 2. Стек

**Frontend (`frontend/`)**: Vite, React 19, TypeScript strict, Zustand + Immer (patches → undo/redo), таймлайн на Canvas 2D, превью/рендер WebGL2 (+ twgl.js), Mediabunny (декод/мукс MP4), WebCodecs, Web Audio API, Vitest, Playwright, MSW (моки API).

**Backend (`backend/`)**: Python 3.12, uv, FastAPI + uvicorn, Pydantic v2, numpy/scipy, librosa, soundfile, ffmpeg/ffprobe (бинарь), rife-ncnn-vulkan (бинарь), Demucs (опц. extra, тянет torch), google-genai, pytest.

**Desktop (фаза 8)**: Tauri 2, Python-бэк как sidecar (PyInstaller).

## 4. Фазы

Каждая фаза = вертикальный срез, который можно показать. Внутри фазы фронт и бэк работают параллельно; в конце — **точка интеграции** (чек-лист ниже), которую проверяет оркестратор.

| # | Фаза | Frontend | Backend | Точка интеграции |
|---|---|---|---|---|
| 0 | Фундамент | скелет Vite, layout, MSW-моки, health | скелет FastAPI, health, jobs+WS, хранилище | оба стартуют одной командой, фронт показывает статус бэка |
| 1 | Медиа и таймлайн | дорожки, клипы, плейхед, зум, привязка, трим, сплит, undo, воспроизведение | импорт, ffprobe, прокси, превью-кадры, waveform, Range-стриминг, CRUD проектов | импорт видео+mp3 → на таймлайн → синхронное воспроизведение |
| 2 | Музыка и маркеры | маркеры: отрисовка, порог, M/Delete/drag, бокс-селект, навигация | бас-онсеты, биты, BPM, даунбиты, секции, сила, кэш; Demucs опц. | бас-маркеры совпадают с ударами на слух, правятся руками |
| 3 | Монтаж под бит | «нарезать по маркерам», привязка краёв к маркерам, ripple | ИИ-анализ клипов (старт фазы 7a), motion energy | клипы раскладываются по битам одной кнопкой |
| 4 | Эффекты | WebGL-рендерер, композитинг, шейдеры из реестра, инспектор, «применить к маркерам», переходы, пресеты | хранение пресетов, валидация `effects.json` | шейк/зум/фликер на каждый бас в реальном времени ≥ 30 fps на 1080p-прокси |
| 5 | Speed ramp | модель кривой, граф-редактор, пресеты, запрос интерполяции, сэмплинг | RIFE-пайплайн, производные ассеты, кэш, fallback minterpolate | «быстро–медленно–быстро» в слоте между маркерами, плавное замедление |
| 6 | Экспорт | офлайн-рендер, WebCodecs, аудиомикс, Mediabunny, прогресс/отмена | mezzanine для неподдерживаемых кодеков, экспорт в AE `.jsx` | MP4 совпадает с превью кадр в кадр |
| 7 | ИИ (Gemini) | ИИ-панель, превью ops, мастер автоэдита, моменты на клипах | анализ клипов/музыки, копилот → ops, автоэдит, стиль по референсу | команда «шейк на каждый сильный бас в дропе» → корректные ops → undo работает |
| 8 | Полировка и десктоп | Tauri, автосейв, горячие клавиши, производительность | sidecar-сборка, настройки ключа API, логи | установщик .exe, работает без терминала |

Оркестр.:  [P0]  ·  инт.1 ·  инт.2 ·  инт.3/4  ·  инт.5 · инт.6 · инт.7 · P8

Бэк объективно быстрее на ранних фазах, поэтому ИИ-анализ клипов (7a) и RIFE (5) он начинает раньше, чем фронт до них дойдёт. Фронт никогда не ждёт бэк: всё, что нужно от API, есть в `shared/fixtures` и мокается через MSW (`npm run dev:mock`).

### 4.2 Чек-листы точек интеграции

**Инт.0** — `npm run dev` в корне поднимает фронт и бэк; `GET /api/health` → зелёный индикатор; WS-событие `hello` получено.

**Инт.1** — импорт 2 видео (H.264 и HEVC) и 1 mp3; прокси, превью-кадры и waveform появляются по WS-событиям; клипы перетаскиваются, триммятся, режутся (`Ctrl+K`), липнут к плейхеду и краям; воспроизведение аудио и видео без рассинхрона > 1 кадра за 60 с.

**Инт.2** — анализ трека < 10 с на 3-минутный mp3; маркеры видны на аудиоклипе; порог силы скрывает слабые; `M`, `Delete`, drag, бокс-селект; маркеры двигаются вместе с аудиоклипом.

**Инт.3/4** — «Нарезать по маркерам» раскладывает выбранные клипы; эффекты из реестра применяются к маркерам по фильтру; превью ≥ 30 fps.

**Инт.5** — пресет «Fast–Slow–Fast» на клипе; бэк возвращает интерполированный ассет; в превью замедленная часть плавная; пока задача идёт — fallback на frame blending.

**Инт.6** — экспорт 1080p60 30-секундного эдита; сравнение 10 случайных кадров экспорта и превью (PSNR > 40 dB); звук синхронен.

**Инт.7** — 10 эталонных команд из `shared/fixtures/ai_commands.json` дают валидные ops; автоэдит на 3 клипа + трек даёт проект без перекрытий и с клипами точно по маркерам.

## 5. Как использовать ИИ (Gemini)

| Функция | Модель | Вход | Выход |
|---|---|---|---|
| Анализ клипа | Pro (или Flash, низкое разрешение медиа) | прокси 360p через Files API | моменты `{start,end,score,tags,description}`, тип плана, лица/объекты |
| Семантика трека | Flash | аудио + DSP-секции | подписи секций (intro/build/drop/break/outro), энергия, настроение |
| Копилот | Flash | сжатое описание проекта + выделение + плейхед + команда | `{ops[], explanation}` по JSON-схеме |
| Автоэдит | Pro | слоты из маркеров + моменты клипов + стиль | назначение моментов в слоты + предложения эффектов → бэк детерминированно собирает ops |
| Стиль по референсу | Pro | чужой эдит | `StylePreset`: склеек в секунду по секциям, эффекты, частоты, ramp-паттерны |

Принципы: ИИ никогда не применяет изменения молча (превью → «Применить»); всё, что ИИ возвращает, валидируется Pydantic + проверкой ID; результаты анализа кэшируются по хэшу файла; имена моделей — в `.env` (`GEMINI_MODEL_FAST`, `GEMINI_MODEL_PRO`); ключ API только на бэке.

## 6. Как запускать агентов

1. **Фазу 0 делает один агент последовательно** (или оркестратор): `git init`, структура, `shared/` (схемы, `effects.json`, фикстуры), оба скелета, `CLAUDE.md`. Параллельная работа начинается только после инт.0.
2. Далее два агента в **отдельных git worktree** (`isolation: "worktree"`), ветки `feat/frontend-pN` и `feat/backend-pN`. Каждый агент правит только свою папку.
3. **Изменение контракта** (`shared/`, `docs/CONTRACT.md`) — только через оркестратора: агент пишет предложение в `docs/CONTRACT_CHANGES.md` (раздел «Proposed»), оркестратор утверждает, правит `shared/`, поднимает `schemaVersion`, регенерирует типы и мержит в `main`; агенты делают rebase.
4. В конце фазы агент: тесты зелёные, обновлён чек-лист в своём `docs/*.md` (отметить `[x]`), короткий отчёт: что сделано, что отложено, какие изменения контракта нужны.
5. Оркестратор мержит обе ветки, проходит чек-лист интеграции, запускает следующую фазу.

Правь только `frontend/`. API бэка не жди — используй MSW-моки по `shared/fixtures`. Если контракта не хватает — не меняй `shared/`, а допиши предложение в `docs/CONTRACT_CHANGES.md`. В конце: `npm run typecheck && npm test` зелёные, отметь выполненные пункты, напиши отчёт.

### Промпт для агента бэка

> Ты бэкенд-агент проекта AIEditor (`D:\Programming\AIEditor`). Прочитай `CLAUDE.md`, `PLAN.md`, `docs/CONTRACT.md`, `docs/BACKEND.md`. Выполни фазу **N** из `docs/BACKEND.md`. Правь только `backend/` и `tools/`. Ответы API должны валидироваться по `shared/schema` и совпадать по форме с `shared/fixtures`. Если контракта не хватает — не меняй `shared/`, а допиши предложение в `docs/CONTRACT_CHANGES.md`. В конце: `uv run pytest` и `uv run ruff check` зелёные, отметь выполненные пункты, напиши отчёт.

## 7. Риски

| Риск | Митигация |
|---|---|
| Рассинхрон превью и экспорта | один рендерер (WebGL) для обоих; тест PSNR на инт.6 |
| Браузер не декодирует исходник (ProRes, некоторые HEVC) | бэк делает mezzanine H.264 CRF 16, флаг `browserDecodable` |
| Неточный seek `<video>` при скрабе | прокси с GOP 10, превью-кадры при быстром скрабе, точный декод Mediabunny на паузе |
| Gemini возвращает невалидные ops | JSON-схема в запросе, Pydantic-валидация, одна повторная попытка с текстом ошибок |
| Лимиты/стоимость Gemini на видео | прокси 360p, низкое разрешение медиа, кэш по хэшу, анализ один раз на ассет |
| RIFE медленный на длинных участках | интерполировать только диапазон с speed < 1, кэш, прогресс в UI, fallback на frame blending |
| Demucs тяжёлый (torch) | опциональный extra, по умолчанию бас через фильтр нижних частот |
| Расползание контракта при параллельной работе | изменения только через оркестратора, `schemaVersion`, общие фикстуры как тесты |
